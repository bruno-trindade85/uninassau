04 — Funcionamento

O fluxo básico da aplicação

Usuário preenche→Evento submit→Array recebe dados→DOM é atualizado

Navegação SPA

Os botões do menu não abrem novos arquivos HTML. O JavaScript troca o conteúdo exibido dentro de #app.

Dados temporários

Os registros ficam em um array enquanto a página está aberta. Não existe banco de dados nesta atividade.

Manipulação do DOM

O sistema utiliza recursos como querySelector, innerHTML, addEventListener e classList.

Ação sobre dados

No exemplo, o aluno pode excluir um registro. No seu estudo de caso, a ação poderá ser adaptada.

07 — Parte 2

Desmembre o arquivo fornecido

O código inicial está propositalmente todo dentro de um único HTML. Depois de adaptar a aplicação, você deverá organizar o projeto.

projeto-spa/ │ ├── index.html │ ├── css/ │ └── style.css │ └── js/ └── app.js

O que vai para cada arquivo?

index.html — estrutura HTML.

css/style.css — todo o conteúdo que estava dentro de <style>.

js/app.js — todo o conteúdo que estava dentro de <script>.

Depois da separação, o sistema precisa continuar funcionando normalmente.

No index.html: use <link rel="stylesheet" href="css/style.css"> e <script src="js/app.js"></script>.

09 — Requisitos mínimos
Checklist da atividade




Escolher um dos 10 estudos de caso.


Adaptar títulos, telas, campos e dados para o tema escolhido.


Possuir tela inicial e pelo menos três outras telas/áreas.


Navegar entre as telas sem recarregar a página.


Utilizar pelo menos um formulário.


Guardar temporariamente os dados em um array JavaScript.


Listar dinamicamente os dados usando o DOM.


Implementar pelo menos uma ação sobre os dados.


Separar HTML, CSS e JavaScript em arquivos diferentes.


Garantir que a aplicação continue funcionando depois da organização.
