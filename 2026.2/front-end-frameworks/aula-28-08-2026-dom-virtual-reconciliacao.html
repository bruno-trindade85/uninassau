Renderização, DOM Virtual e Reconciliação

Como frameworks modernos transformam mudanças nos dados em mudanças visuais na tela — e por que isso importa para desempenho e experiência do usuário.

Pergunta-guia: se somente o número de itens do carrinho mudou de 2 para 3, faz sentido reconstruir toda a página?

Nesta aula vamos acompanhar o caminho completo de uma atualização: ação do usuário → mudança de estado → nova representação → comparação → atualização necessária no DOM.

Fundamento

DOM — Document Object Model

O DOM é a representação estruturada que o navegador cria a partir do HTML.

Quando o navegador recebe um arquivo HTML, ele interpreta as tags e cria objetos em memória. Cada elemento passa a ser um nó de uma árvore. Essa estrutura permite que JavaScript encontre, leia, crie, remova ou altere elementos depois que a página já foi carregada.

Do código à tela

Renderização

Renderizar é transformar estrutura, estilos e dados em pixels visíveis.

Depois que o navegador conhece DOM e CSS, ele calcula tamanho e posição dos elementos, desenha suas propriedades visuais e combina as camadas para formar a imagem final.

Layout / Reflow

Recalcula tamanho e posição quando uma mudança afeta a geometria.

Repaint

Redesenha elementos quando propriedades visuais mudam.

Composição

Combina as camadas até produzir a tela final.

Dados da aplicação

Estado

Estado é o conjunto de dados que representa a situação atual da aplicação.

Quantidade no carrinho, usuário autenticado, filtros, texto digitado, dados vindos de API e página atual são exemplos de estado. Quando o estado muda, a interface precisa refletir o novo valor.

Paradigma

Imperativo × Declarativo

No modelo imperativo, o programador descreve passo a passo o que deve mudar no DOM. No declarativo, ele descreve como a interface deve ficar para um determinado estado e o framework calcula as operações necessárias.

Imperativo

const qtd = document.querySelector('#qtd');qtd.textContent = '3 itens';

“Encontre o elemento e faça esta alteração.”

Declarativo

estado.quantidade = 3UI = função(estado)→ mostrar '3 itens'

“Para este estado, a interface deve ficar assim.”

Ideia central: UI = função(estado).
Representação em memória

Virtual DOM

Alguns frameworks criam representações da interface em memória para comparar versões antes de alterar o DOM real.

Quando o estado muda, uma nova representação é produzida. A anterior e a nova podem ser comparadas para descobrir quais nós realmente mudaram.

Comparação

Diffing

Diffing é a comparação entre duas representações da interface para identificar diferenças.

Se uma lista ganhou somente um novo aluno, a comparação pode concluir que os itens anteriores continuam iguais e somente um novo elemento precisa ser inserido.

Antes

<li>Ana</li><li>Bruno</li>

  • Bruno

<li>Ana</li><li>Bruno</li><li>Carla</li>
turma.exemplo.com
  • Ana
  • Bruno
  • Carla
Resultado: inserir apenas “Carla”.
Aplicação das mudanças

Reconciliação

Reconciliação é o processo de decidir como transformar a interface antiga na nova.

O diffing encontra as diferenças; a reconciliação converte essas diferenças em operações concretas no DOM real. Frameworks usam heurísticas para tornar esse processo rápido e previsível.

Identidade

Keys em listas

Em listas dinâmicas, o framework precisa reconhecer se um item já existia, foi removido ou apenas mudou de posição. Uma key funciona como identidade estável.

Sem key estável

Ana
Bruno
Carla

A posição pode ser confundida com a identidade.

Com keys

{ id: 17, nome: 'Ana' }{ id: 42, nome: 'Bruno' }{ id: 91, nome: 'Carla' }

Mesmo mudando de posição, cada item continua reconhecível.

Conceito-chave

Re-renderizar não é reconstruir tudo

Re-renderização significa que a lógica que descreve determinada parte da interface é executada novamente. Isso não implica necessariamente remover e recriar todo o DOM real.

1. Estado

Um dado muda.

2. Representação

Uma nova descrição da interface é produzida.

3. DOM

Somente mudanças necessárias são aplicadas.

Além do Virtual DOM

Nem todo framework usa a mesma estratégia

O objetivo é manter interface e estado sincronizados. O Virtual DOM é apenas uma abordagem possível.

Virtual DOM

Compara representações em memória.

Reatividade granular

Rastreia dependências específicas e atualiza apenas as partes ligadas ao dado alterado.

Compilação

Parte das decisões pode ser antecipada durante o build.
