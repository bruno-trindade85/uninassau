Bloco 1 · Assunto 01 de 13

Promises

Programação assíncrona e tratamento de erros

O que é?

Conceito

Uma Promise representa o resultado futuro de uma operação assíncrona. Ela pode ser concluída com sucesso ou rejeitada com erro.

Para que serve?

Aplicação prática

Esperar o resultado de uma consulta sem bloquear outras tarefas do servidor.

Como funciona?

Exemplo prático

O sistema solicita o aluno de matrícula 7. Quando a consulta termina, exibe os dados; se falhar, apresenta uma mensagem de erro.

Fluxo de exemplo
Iniciar consulta→Promise resolve ou rejeita→Usar resultado ou tratar erro
Bloco 1 · Assunto 02 de 13

Async/Await

Programação assíncrona e tratamento de erros

O que é?

Conceito

Async/Await é uma sintaxe para trabalhar com Promises usando um fluxo de leitura semelhante ao código sequencial.

Para que serve?

Aplicação prática

Organizar consultas a APIs ou bancos de dados com código mais claro e fácil de acompanhar.

Como funciona?

Exemplo prático

Uma função assíncrona usa await para obter a lista de alunos antes de preparar a resposta da API.

Fluxo de exemplo
Chamar função async→Aguardar com await→Continuar com os dados
Bloco 1 · Assunto 03 de 13

Tratamento de erros (Try/Catch)

Programação assíncrona e tratamento de erros

O que é?

Conceito

Try/Catch permite capturar exceções que ocorram durante a execução de um trecho de código.

Para que serve?

Aplicação prática

Lidar com falhas de rede, banco de dados ou processamento e responder de forma controlada.

Como funciona?

Exemplo prático

Se a consulta ao banco falhar, a API registra a ocorrência e retorna uma resposta de erro apropriada, em vez de expor detalhes internos.

Fluxo de exemplo
Executar try→Capturar falha no catch→Responder com segurança
Bloco 2 · Assunto 04 de 13

Integração com banco de dados

Integração com banco de dados

O que é?

Conceito

É a comunicação da aplicação com um sistema que armazena e organiza informações de maneira persistente.

Para que serve?

Aplicação prática

Cadastrar, listar, alterar e excluir registros por meio das operações CRUD.

Como funciona?

Exemplo prático

Na API de alunos, uma requisição de cadastro salva nome e matrícula no banco; uma consulta posterior recupera esse registro.

Fluxo de exemplo
Receber requisição→Consultar ou gravar dados→Devolver resposta
Bloco 2 · Assunto 05 de 13

ORMs (Mapeadores Objeto-Relacionais)

Integração com banco de dados

O que é?

Conceito

Um ORM faz o mapeamento entre objetos da aplicação e tabelas de um banco relacional.

Para que serve?

Aplicação prática

Simplificar operações de persistência e a organização dos modelos de dados.

Como funciona?

Exemplo prático

Com Prisma, o código cria um objeto Aluno e o ORM gera a operação necessária para gravar o registro no banco configurado.

Fluxo de exemplo
Criar objeto Aluno→ORM mapeia para a tabela→Banco salva registro
Bloco 3 · Assunto 06 de 13

Consumo de APIs externas

Integração com APIs externas

O que é?

Conceito

É a utilização de serviços oferecidos por outro sistema por meio de requisições de rede.

Para que serve?

Aplicação prática

Adicionar funcionalidades sem desenvolver todos os dados ou serviços do zero.

Como funciona?

Exemplo prático

Ao digitar um CEP, o cadastro consulta o ViaCEP e preenche endereço, bairro e cidade com as informações recebidas.

Fluxo de exemplo
Enviar CEP→Receber resposta JSON→Preencher formulário
Bloco 3 · Assunto 07 de 13

Timeouts

Integração com APIs externas

O que é?

Conceito

É um limite de tempo estabelecido para esperar a conclusão de uma operação.

Para que serve?

Aplicação prática

Impedir que uma integração fique aguardando indefinidamente um serviço lento.

Como funciona?

Exemplo prático

A API define um prazo de cinco segundos para consultar um serviço de endereços; vencido o tempo, cancela a solicitação e informa a falha.

Fluxo de exemplo
Iniciar requisição→Contar até 5 segundos→Concluir ou cancelar
Bloco 3 · Assunto 08 de 13

Degradação graciosa

Integração com APIs externas

O que é?

Conceito

É uma estratégia para manter as funções essenciais disponíveis quando uma dependência apresenta falhas.

Para que serve?

Aplicação prática

Oferecer uma alternativa segura ou uma funcionalidade reduzida durante indisponibilidades.

Como funciona?

Exemplo prático

Se a API de endereços ficar fora do ar, o aluno ainda pode concluir o cadastro preenchendo o endereço manualmente.

Fluxo de exemplo
Serviço externo falha→Ativar alternativa→Manter cadastro disponível
Bloco 3 · Assunto 09 de 13

Processamento em lote

Integração com APIs externas

O que é?

Conceito

Consiste em dividir um conjunto de tarefas ou registros em grupos menores para processamento organizado.

Para que serve?

Aplicação prática

Controlar o volume de trabalho e reduzir a sobrecarga ao lidar com muitos dados.

Como funciona?

Exemplo prático

Para atualizar 50 produtos, o sistema processa cinco grupos de 10 registros, em vez de disparar todas as operações sem controle.

Fluxo de exemplo
Separar 50 registros→Processar lotes de 10→Consolidar resultados
Bloco 4 · Assunto 10 de 13

Proteção de senhas e Salting

Segurança em aplicações Back-End

O que é?

Conceito

Senhas devem ser protegidas com funções de hash próprias para senhas; o salt é um valor aleatório usado para diferenciar resultados.

Para que serve?

Aplicação prática

Evitar armazenar senhas em texto puro e dificultar ataques sobre hashes vazados.

Como funciona?

Exemplo prático

No cadastro, bcrypt gera um hash com salt para a senha; no login, o sistema verifica a senha informada contra esse hash.

Fluxo de exemplo
Receber senha→Gerar hash com salt→Armazenar só o hash
Bloco 4 · Assunto 11 de 13

Autenticação com JWT

Segurança em aplicações Back-End

O que é?

Conceito

JWT é um formato de token que pode carregar declarações assinadas para verificação de autenticidade.

Para que serve?

Aplicação prática

Identificar sessões autenticadas em requisições às rotas protegidas da API.

Como funciona?

Exemplo prático

Após o login, a API emite um token assinado. Ao acessar /perfil, verifica a assinatura e a validade antes de autorizar a ação.

Fluxo de exemplo
Login válido→Emitir token assinado→Verificar token na rota
Bloco 4 · Assunto 12 de 13

CORS

Segurança em aplicações Back-End

O que é?

Conceito

CORS é o mecanismo usado pelos navegadores para controlar o acesso a respostas de recursos entre diferentes origens.

Para que serve?

Aplicação prática

Configurar quais origens do Front-End podem ler respostas da API no navegador.

Como funciona?

Exemplo prático

A API permite a origem do site da escola para que o navegador aceite suas respostas. CORS não substitui autenticação nem autorização.

Fluxo de exemplo
Navegador envia origem→API informa regra CORS→Navegador aplica a regra
Bloco 4 · Assunto 13 de 13

Cabeçalhos de segurança

Segurança em aplicações Back-End

O que é?

Conceito

São campos na resposta HTTP que orientam o navegador a aplicar determinadas proteções.

Para que serve?

Aplicação prática

Reduzir riscos associados à interpretação ou incorporação indevida de conteúdo web.

Como funciona?

Exemplo prático

Uma aplicação Express utiliza Helmet para configurar cabeçalhos de segurança, como opções contra interpretação incorreta do tipo de conteúdo.

Fluxo de exemplo
API prepara resposta→Adicionar cabeçalhos→Navegador aplica proteções
