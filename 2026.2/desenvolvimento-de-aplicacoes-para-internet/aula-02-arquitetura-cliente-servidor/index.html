Conceito central

Arquitetura Cliente-Servidor

A arquitetura cliente-servidor é o modelo em que uma aplicação é dividida entre quem solicita um serviço e quem processa essa solicitação.

💻Cliente

O cliente normalmente é o navegador ou aplicativo usado pelo usuário. Ele solicita páginas, dados, autenticações, arquivos ou operações ao servidor.

→
🖥️Servidor

O servidor recebe a requisição, executa alguma lógica, acessa dados quando necessário e devolve uma resposta adequada ao cliente.

Exemplo: quando o aluno acessa um site de notícias, o navegador é o cliente. O servidor recebe a solicitação e envia a página ou os dados solicitados.
Papéis da comunicação

Cliente e Servidor

Cliente

O cliente é o software que inicia a comunicação. Em aplicações web, geralmente é o navegador, como Chrome, Edge ou Firefox, mas também pode ser um aplicativo mobile ou outro sistema.

A principal ideia é: o cliente pede alguma coisa ao servidor. Ele pode pedir uma página, enviar dados de um formulário, solicitar uma lista de produtos ou tentar realizar um login.

Servidor

O servidor é o software responsável por receber requisições e devolver respostas. Ele pode executar regras de negócio, consultar banco de dados, autenticar usuários e acessar outros serviços.

Servidor não significa apenas “um computador grande”. No contexto da web, servidor é principalmente um software que está aguardando requisições.

Mensagens da web

Requisição e Resposta

Requisição — Request

A requisição é a mensagem enviada pelo cliente ao servidor solicitando alguma operação. Essa operação pode ser carregar uma página, buscar uma lista de usuários, cadastrar um produto ou fazer login.

// Exemplo conceitualCliente → "Quero os dados do usuário 25" → Servidor

Resposta — Response

A resposta é a mensagem enviada pelo servidor após processar a requisição. Essa resposta pode conter HTML, JSON, uma imagem, um arquivo ou apenas uma informação dizendo se a operação foi realizada com sucesso.

// Exemplo conceitualServidor → "Dados solicitados" → Cliente
Ideia essencial: a web funciona como uma conversa. O cliente pergunta ou envia algo; o servidor interpreta, processa e responde.
Imagem do fluxo

Ciclo de Requisição e Resposta

Esse é o funcionamento básico de uma aplicação web. O usuário interage com o navegador, o navegador envia uma requisição, o servidor processa essa solicitação e devolve uma resposta que será apresentada novamente ao usuário.

Frase para fixar: a web funciona por meio de trocas de requisições e respostas.
Ligação com a aula anterior

Front-End e Back-End dentro da arquitetura

O Front-End normalmente executa no cliente e apresenta a interface ao usuário. O Back-End executa no servidor e processa regras, dados e operações.

🎨Front-End

É a parte visual e interativa da aplicação. Usa HTML, CSS e JavaScript para apresentar telas, botões, formulários e mensagens ao usuário.

⇄
⚙️Back-End

É a parte responsável por regras de negócio, autenticação, acesso ao banco de dados, validações e geração de respostas para o cliente.

Como a conversa acontece

Comunicação entre Cliente e Servidor

Cliente e servidor precisam seguir determinadas regras para conseguirem se comunicar. Na web, essa comunicação normalmente acontece usando HTTP ou HTTPS.

HTTP / HTTPS

HTTP e HTTPS são protocolos usados para organizar a comunicação entre cliente e servidor. Nesta aula, eles aparecem como introdução, pois serão aprofundados na próxima aula.

URL

A URL indica para onde a requisição será enviada. Ela funciona como o endereço do recurso que o cliente deseja acessar.

https://meusite.com/produtos

Recurso

Um recurso pode ser uma página, uma lista de produtos, um usuário, uma imagem ou uma funcionalidade disponível em uma aplicação.

Troca de dados

Dados enviados entre Cliente e Servidor

Nem toda requisição busca uma página completa. O cliente e o servidor também podem trocar dados. Atualmente, APIs geralmente utilizam JSON por ser um formato simples, legível e muito usado em aplicações web.

Exemplo de JSON

{ "nome": "Maria", "curso": "ADS"}

Conexão com a aula anterior

Na aula de introdução ao Back-End, JSON apareceu como uma forma de representar dados. Nesta aula, ele entra no fluxo de comunicação: o cliente pode enviar JSON e o servidor pode responder com JSON.

Aplicação prática

Exemplo real: fluxo de login

O login é um ótimo exemplo porque junta interface, requisição, servidor, banco de dados, validação e resposta.

Passo a passo

1. O usuário digita e-mail e senha. 2. O Front-End envia esses dados. 3. O servidor recebe a requisição. 4. O servidor consulta o banco de dados. 5. O servidor verifica as credenciais. 6. O servidor envia uma resposta. 7. O Front-End mostra o resultado ao usuário.

O que observar

O aluno deve perceber que clicar em um botão não é apenas uma ação visual. Esse clique pode iniciar uma comunicação completa entre cliente e servidor, envolvendo envio de dados, processamento e retorno de uma resposta.

Formulário→Request→Servidor→Banco→Response
