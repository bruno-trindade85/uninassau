1. Conceito principal

O que é Node.js?

Node.js é um ambiente de execução que permite rodar JavaScript fora do navegador.

Antes

JavaScript ficou conhecido principalmente por executar dentro do navegador e controlar páginas Web.

Com Node.js

O mesmo JavaScript pode executar diretamente no computador ou em um servidor.

Resultado

JavaScript também pode ser utilizado para desenvolver a parte Back-End de aplicações.

Definição para lembrar: navegador executa JavaScript no Front-End; Node.js permite executar JavaScript fora do navegador, inclusive no Back-End.
2. Utilidade

Para que serve o Node.js?

Ele permite usar JavaScript para construir a parte da aplicação que trabalha no servidor.

Criar servidores

Receber requisições enviadas por navegadores, aplicativos e outros sistemas.

Criar APIs

Disponibilizar dados e funcionalidades para diferentes aplicações.

Processar regras

Executar login, cadastros, cálculos, validações e outras regras da aplicação.

Acessar dados

Ler arquivos, consultar bancos de dados e comunicar-se com serviços externos.

Exemplo: o usuário envia login e senha. O Node.js pode receber os dados, verificar o usuário no banco e devolver a resposta.
3. Executando JavaScript

Um primeiro programa com Node.js

Um arquivo JavaScript pode ser executado diretamente pelo terminal.

const mensagem = "Servidor iniciado";console.log(mensagem);
app.js→node app.js→Servidor iniciado
O ponto importante: não precisamos abrir esse código em uma página HTML. O Node.js executa o JavaScript diretamente.

5. Servidor Web

Node.js pode funcionar como servidor

O programa fica em execução aguardando requisições. Quando uma requisição chega, ele executa uma ação e produz uma resposta.

NavegadorGET /produtos →Node.js→Busca dados→JSON

Requisição

O cliente pede alguma informação ou solicita uma ação.

Resposta

O Node.js processa o pedido e devolve dados, uma mensagem ou um código de status.

6. Funcionamento

Como o Node.js trabalha?

Uma característica importante é trabalhar muito bem com tarefas que envolvem espera, como rede, arquivos, APIs e banco de dados.

Orientado a eventos

O programa reage quando algo acontece: chega uma requisição, termina uma leitura ou uma consulta retorna.

Não bloqueante

Em muitas operações, o programa não precisa ficar parado esperando a tarefa terminar para continuar trabalhando.

Exemplo: enquanto uma consulta ao banco aguarda resposta, o Node.js pode continuar recebendo outras requisições.
7. Comparação

Síncrono × Assíncrono

Síncrono

Uma tarefa precisa terminar antes que a próxima continue.

Tarefa A→Espera→Tarefa B

Exemplo: ler completamente um arquivo antes de executar a próxima instrução.

Assíncrono

Uma operação pode ser iniciada e o programa continua outras tarefas enquanto aguarda.

Tarefa A↗Aguardando↘Continua

Exemplo: consultar uma API e continuar trabalhando enquanto a resposta não chega.

8. Entrada e saída

Operações de I/O e espera

I/O (Input/Output) são operações em que o programa se comunica com algo externo.

Arquivo

Ler ou gravar informações no disco.

Banco de dados

Consultar, cadastrar ou atualizar dados.

Rede / API

Enviar uma requisição e aguardar uma resposta externa.

Por que isso importa? essas tarefas podem demorar. O modelo não bloqueante ajuda o Node.js a aproveitar esse tempo para cuidar de outras operações.
9. Coordenação

Event Loop — a ideia sem complicar

O Event Loop ajuda a coordenar quando as tarefas que estavam aguardando podem continuar.

Requisição A→Consulta ao banco⏳Node atende B→Banco respondeu→Continua A
Não precisa decorar detalhes internos agora. A ideia essencial é: uma tarefa que está esperando não precisa impedir o Node.js de continuar cuidando de outras tarefas.
