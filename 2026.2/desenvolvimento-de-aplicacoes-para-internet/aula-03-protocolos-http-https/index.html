1. Fundamento

HTTP — Hypertext Transfer Protocol

HTTP é o protocolo que define como clientes e servidores trocam mensagens na Web.

O que é?

Um conjunto de regras de comunicação que organiza pedidos e respostas.

Para que serve?

Permite abrir páginas, carregar imagens, enviar formulários e consumir APIs.

Exemplo: GET /alunos. O servidor consulta os dados e responde.
2. Segurança

HTTPS — HTTP Secure

HTTPS é HTTP transportado por uma conexão protegida por TLS.

O que faz?

Protege os dados em trânsito contra leitura e alteração indevida.

Onde aparece?

Login, bancos, lojas virtuais, sistemas acadêmicos e aplicações Web modernas.

https://sistema.com/login{ "email": "aluno@email.com", "senha": "minhaSenha123" }
3. Request

Requisição HTTP

É a mensagem que o cliente envia ao servidor solicitando uma ação.

Partes principais

Método: ação. URL: recurso. Headers: informações adicionais. Body: dados enviados.

Exemplo

Um formulário de cadastro pode gerar uma requisição POST com os dados do novo usuário.

POST /usuarios HTTP/1.1Content-Type: application/json{ "nome": "Maria", "email": "maria@email.com" }
4. Response

Resposta HTTP

É a mensagem devolvida pelo servidor depois que a requisição foi processada.

Ela informa: o resultado por meio do código de status e, quando necessário, os dados retornados.
HTTP/1.1 200 OKContent-Type: application/json{ "id": 10, "nome": "Maria" }
5. Métodos HTTP

GET — Consultar

Busca informações de um recurso.

Exemplo: GET /alunos/2 solicita os dados do aluno de ID 2. Uso comum: listar produtos, usuários, notícias e pedidos.
6. Métodos HTTP

POST — Criar

Cria normalmente um novo recurso no servidor.

POST /alunos{ "nome": "João", "curso": "ADS" }→ 201 Created
7. Métodos HTTP

PUT — Substituir/atualizar

Envia uma nova representação de um recurso existente, normalmente substituindo seus dados.

PUT /alunos/3{ "nome": "João Silva", "curso": "ADS" }
8. Métodos HTTP

PATCH — Atualizar parcialmente

Altera apenas parte de um recurso.

PUT

Representação completa ou substitutiva.

PATCH

Somente a alteração necessária.

PATCH /alunos/3{ "curso": "Sistemas de Informação" }
9. Métodos HTTP

DELETE — Excluir

Solicita a remoção de um recurso identificado pela URL.

Usuário clica “Excluir”→DELETE /alunos/3→Servidor remove
10. Estrutura da mensagem

Cabeçalhos — Headers

São metadados enviados junto com requisições e respostas.

Content-Type

Informa o formato dos dados, como application/json.

Authorization

Pode transportar uma credencial ou token de autenticação.

Content-Type: application/jsonAuthorization: Bearer token123
11 e 12. Dados

Corpo da requisição e JSON

O body transporta os dados enviados ao servidor. JSON é um dos formatos mais usados para representá-los.

{ "nome": "Notebook", "preco": 3500}
13. Resultado

Códigos de status HTTP

Informam ao cliente o resultado da requisição.

CódigoSignificadoExemplo
200 OKSucessoConsulta retornou dados.
201 CreatedRecurso criadoNovo aluno cadastrado.
204 No ContentSucesso sem corpoExclusão concluída.
400Requisição inválidaCampo obrigatório ausente.
401Autenticação inválidaAcesso protegido sem login válido.
403Sem permissãoUsuário comum tenta ação de admin.
404Não encontradoAluno solicitado não existe.
500Erro internoFalha inesperada no servidor.
14. Segurança

Segurança da comunicação

No HTTPS, TLS protege a comunicação enquanto os dados trafegam entre cliente e servidor.

Confidencialidade

Dificulta a leitura dos dados por terceiros.

Integridade

Ajuda a detectar alterações durante o transporte.

Autenticação

O certificado ajuda a verificar a identidade do servidor.

Importante: HTTPS protege o transporte, mas não substitui validação, autenticação e autorização no Back-End.

O fluxo que você precisa guardar

O cliente envia uma requisição. O método informa a intenção. A URL identifica o recurso. Headers e body carregam informações. O servidor processa e devolve uma resposta com status e, muitas vezes, JSON.

Cliente→Método + URL→Headers / Body→Servidor→Status + JSON
